## Сделано по контенту (обновляется)
- ✅ 71 модель FBX/GLB + превью: оружие 9, персонажи 7, пропсы/стройка 26, транспорт 5, деплои 22,
  лут-контейнеры 7 (ящик/сейф/бочки/тулбокс/медшкаф/айрдроп)
- ✅ Все точки-заглушки в коде переведены на `World/ModelLibrary` (монстры, лут, лифты, транспорт,
  мешок с лутом, деплои) — модель подставляется, если префаб собран, иначе остаётся примитив
- ✅ Постановка деплоев из инвентаря (`DeployPlacer`), скины (`Skins.cs`), погода и айрдропы (`World/`)
- ✅ Двери и замки (`Building/Doors.cs` + `UI/CodeLockUI.cs`): створка на петле, код-лок и парный ключ;
  сетевой путь готов (`Net/DeployNet.cs`: Command → валидация → RPC, код замка не покидает сервер)
- ✅ Двойная дверь: две створки по 1 м, открываются навстречу (петли у краёв проёма)
- ✅ Репликация спавна (`Net/SpawnNet.cs`): деплои **и элементы стройки** — сервер создаёт объект,
  клиенты получают `object.spawn`/`object.despawn`, новому игроку высылается мир
  (netId-дубликаты отсекаются, `BuildController.SpawnBlock` — общий путь для локальной и сетевой постановки)

- ✅ Зеркало инвентарей и серверный лут (`Net/InventoryNet.cs`): дельта слотов клиент → сервер,
  списание на сервере (`ServerPay`/`ServerConsume`), адресная выдача (`inv.give` — так приезжает
  ключ от нового замка), открытие/взятие/перекладывание ящиков через сервер (`loot.contents`/`loot.slot`),
  `SpawnNet.RequireServerInventory` включён; в Mirror команды и RPC ходят по netId игрока, а не
  по connectionId (адресная доставка `PlayerRpc`)

- ✅ Сундуки и печи — серверные (`InventoryNet` + `Handle`): содержимое приходит от сервера,
  печь сама обновляет открытые окна после плавки, в UI две сетки — вход и выход (как в Rust);
  изменения рассылаются только тем, у кого контейнер открыт
- ✅ Бой: урон по игрокам считает сервер (`Net/CombatNet.cs`) — монстры, взрывы и огонь бьют
  через `ServerDamage`, удалённой жертве уезжает RPC `dmg`; попадание игрока по игроку
  (`HitPlayer`) проверяется по дистанции, углу и линии видимости, а урон сервер считает сам
  по таблице оружия (число из пакета не принимается); здоровье клиента идёт `PlayerHealth`
  только «вниз» — вылечиться пакетом нельзя; смерть финализирует сервер
- ✅ Предметы на полу и мешок с трупом — серверные: дроп (`LootDrop`) и подбор (`LootPickup`)
  проверяются по дистанции и месту, предмет исчезает через 15 мин; смерть (`PlayerDied`) —
  мешок с лутом собирает сервер из зеркала (нельзя подделать содержимое), труп лежит 15 мин,
  у мёртвого инвентарь обнуляется и у него, и в зеркале
- ✅ Единый формат позиций в сети (−100…900 м): раньше часть сообщений схлопывала отрицательные
  координаты в 0 — деплои и блоки «прилипали» к плоскости x=0
- ✅ Предсказание постановки (`SpawnNet.PredictDeployable`/`PredictBlock`): объект появляется в тот же
  кадр, сервер «усыновляет» предсказание по netId, при отказе — `place.reject` и возврат предмета
  (плюс страховка по таймауту 2.5 с); цена списывается клиентом мгновенно, сервер повторяет в зеркале
